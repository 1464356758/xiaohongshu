# 状态机与写入权限
每条内容一个task_id；用户实际发布的一条笔记对应一个content_id，二者不混用。

| 当前状态 | 必须具备的证据 | 后继 | 推进人 |
|---|---|---|---|
| READY | 正式任务、输入版本、负责人 | PLANNING | 总监 |
| PLANNING | 策划交付经总监验收 | SCRIPTING | 总监 |
| SCRIPTING | 脚本交付和拍摄单 | WAITING_ASSETS | 总监 |
| WAITING_ASSETS | 本人真实素材及体验记录 | PRODUCING | 总监 |
| PRODUCING | 完整实际媒体、文案与证据 | REVIEWING | 总监 |
| REVIEWING | PASS且绑定精确版本 | APPROVED | 总监 |
| REVIEWING | P0/P1问题 | REVISING | 总监 |
| REVISING | 新版本及逐条回应 | REVIEWING | 总监 |
| APPROVED | 用户执行发布，提供链接 | PUBLISHED | 总监 |
| PUBLISHED | 发布回执核验 | OBSERVING | 总监 |
| OBSERVING | 24h/72h/7d回收、日报 | ARCHIVED | 总监 |
| 任意非终态 | 缺数据、无权限、限额、违规 | BLOCKED或PAUSED | 总监 |
| BLOCKED/PAUSED | 缺项解除且旧任务仍有效 | resume_state | 总监 |

最多2轮返修；第3次审核未通过转PAUSED，由总监补证、换题或CANCELLED，不强行PASS。ARCHIVED表示本轮观察结束，不是永远停止查看；长期数据可追加快照。
品牌修改已审核内容时，批准失效→REVISING→REVIEWING。纯公开发布时间变化可更新排期；文案事实、素材、商品、标识、合作条件变化必须重审。

任务内dependencies是交付清单数组，required=true的全部验证通过才推进；完成标记不等于审核通过。多个产物用各自固定提交，禁止一个角色写“其他角色也通过”。
角色不轮询等待其他角色，缺依赖立即交接。默认同时1个重推理任务，可并行准备不依赖的素材；本版不启动自动多代理、不创建GitHub Actions、不使用API收费调用。

## 防重复与冲突
以task_id+input_revision+role作为幂等键；重试前查已有交付。首次成功产物保留，修改升版本。总监单一聊天持有写进度权；更换总监时记录handoff_epoch，新总监验证旧任务后接管，旧总监停止写入。
每次状态提交先读当前HEAD，基于其创建提交并非强制快进；失败重新读取，合并不相交的产物变更，有同文件冲突则停止交总监。不删除别人新文件，不force。
批准文件绑定artifact_commit及各最终文件SHA256。发布回执绑定批准ID、实际链接与发布时间。同一个content_id已有链接时，默认禁止再次发布。
当前GitHub连接可写全仓，以上是角色行为隔离，不是强安全隔离。需要强隔离时另行实现分支保护和应用权限；本版未配置，不宣称已配置。
